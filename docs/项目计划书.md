# 四川暴雨预警信息网站项目计划书

版本：v1.0  
编制日期：2026-09-27  
工作名称：四川雨情  
仓库名称：sichuan-rain-alert  
状态：需求与实施规划，未接入实时数据、未上线。

## 一、项目目标

建设以手机访问为主、面向四川居民的暴雨预警信息网站。让用户进入页面后快速回答：我的地区是否有官方预警？预计雨有多大？什么时候开始？大约持续多久？

网站聚合官方预警与经过授权的降雨观测、预测数据，帮助居民安排出行和关注防灾信息。网站传播官方信息，不自行发布官方气象预警；防御指引优先采用发布机构的原文。

首版覆盖四川省市州与区县查询。乡镇或精确位置服务仅在数据源确实支持对应分辨率时开放，不能把区县预报包装为用户所在街道的精确预报。

## 二、使用对象与场景

| 使用对象 | 核心场景 | 页面要求 |
|---|---|---|
| 日常居民 | 查看住所、工作地和家人所在地 | 免登录查询、收藏多个地区 |
| 老年居民 | 快速看懂预警和下雨时间 | 大字模式、文字配色、简洁操作 |
| 通勤与接送人员 | 判断未来数小时出行时间 | 开始时间、持续时间、逐小时变化 |
| 山区居民 | 关注强降雨及次生灾害提示 | 官方防御指引与相关官方信息入口 |

山洪、地质灾害、内涝不能由暴雨等级直接推断。相关信息在二期单独接入对应官方来源，不能用降雨色块代替灾害风险图。

## 三、核心需求与信息含义

### 3.1 地区选择

支持“省 → 市州 → 区县”查询；默认先选择地区，不自动申请定位。用户主动选择定位时再请求权限，并显示定位精度及匹配地区。首版收藏地区保存在本机，不要求创建账号。

### 3.2 暴雨等级与分级预警

必须分开显示两类信息：

1. **官方预警**：原样展示来源发布的暴雨预警或预警信号，包括蓝、黄、橙、红中实际发布的等级，以及发布机构、时间、地区、原文、更新与解除状态。不同产品不混用名称；省级暴雨预警与当地暴雨预警信号分别保留来源产品类型。
2. **降雨预测等级**：根据同一累计时段的预测降雨量展示小雨、中雨、大雨、暴雨、大暴雨、特大暴雨。它描述雨量，不能自动生成或替代官方颜色预警。

四川官方附件存在不同地区的暴雨预警信号标准，包括四川盆地、攀西与部分汶川乡镇、甘孜阿坝其他地区等分区。首版不通过统一阈值自行判定官方预警。若未来加入阈值说明，应按地区、产品类型和标准版本配置，并由相关专业人员核对。

### 3.3 预测开始时间

优先显示数据源明确提供的开始时间或时间区间。若只有逐小时降雨预报，可形成“预计降雨开始时段”，例如“今天18:00—19:00”，同时标明“逐小时预报推算”。不能展示为精确到分钟的确定时间。

降雨开始与暴雨时段开始分开：页面分别显示“预计开始降雨”和“预计强降雨时段”。后者只有在数据源提供强降雨过程时间或存在经过验证的判别规则时展示，否则显示“暂无法确定”。不能把未来24小时累计达到暴雨等级的时刻称为暴雨开始时间。

统一使用北京时间 Asia/Shanghai，显示具体日期，跨天写“明天”并同时附日期。已经开始的过程标为“降雨已开始”，不继续显示失效倒计时。

### 3.4 持续时间

分别展示“预计降雨持续时间”“预计强降雨持续时间”和“官方预警有效时间”，三者不能互相替代。

优先使用源数据提供的过程区间；逐小时推算只显示小时级范围，并保存推算规则版本。若过程延伸到预报窗口之外，显示“预计至少持续至明天08:00，结束时间未确定”；开始、结束任一缺失时不编造时长。

### 3.5 颜色区块

颜色块包含文字等级、降雨量、累计时间窗、观测或预测属性。用户无需仅凭颜色辨认信息。首版采用以下自定义雨量配色，色值仅用于产品设计，不代表官方预警图标标准：

| 预测24小时累计降雨量 | 显示等级 | 建议色块 |
|---|---|---|
| 0 mm | 无降雨 | 浅灰 #E5E7EB |
| 大于0且小于0.1 mm | 微量降雨 | 浅青 #CFFAFE |
| 0.1 ≤ R < 10 mm | 小雨 | 青 #67E8F9 |
| 10 ≤ R < 25 mm | 中雨 | 天蓝 #38BDF8 |
| 25 ≤ R < 50 mm | 大雨 | 蓝 #2563EB |
| 50 ≤ R < 100 mm | 暴雨 | 靛蓝 #4F46E5 |
| 100 ≤ R < 250 mm | 大暴雨 | 紫 #9333EA |
| R ≥ 250 mm | 特大暴雨 | 深紫 #581C87 |
| 数据缺失或超时 | 暂无有效数据 | 灰色斜纹，不使用“无降雨”颜色 |

上表依据 GB/T 28592—2012 的24小时降雨量等级设置连续区间，默认必须标注“未来24小时累计预测雨量”，明确起止时间。上线前复核标准是否更新。输入先按来源有效精度处理，不以四舍五入后的展示数值重新判级。

官方预警卡使用来源对应的蓝、黄、橙、红，并明确标注“官方预警”。小时轴采用单独的连续雨量色阶、显示每小时毫米数，不直接套用24小时分级；官方预警、24小时雨量地图、小时轴各自提供图例。

## 四、页面规划

### 4.1 首页：我的地区

自上而下排列：地区选择与收藏 → 当前官方预警 → 降雨等级、预测开始时间和持续时间 → 未来24小时颜色时间轴 → 地区地图入口 → 官方原文与防御指引 → 数据来源和最近更新时间。

概念卡片示例（仅用于设计，非真实预警）：

> 演示数据｜某区县  
> 官方预警：暴雨橙色预警信号（示例）  
> 未来24小时预测：暴雨，累计约65 mm  
> 预计开始降雨：今天18:00—19:00  
> 预计降雨持续：约4—6小时  
> 强降雨时段：暂无法确定  
> 发布机构、预报生成时间、更新时间：按实际来源显示

### 4.2 四川雨情地图

默认展示区县范围的未来24小时预测雨量色块。切换“官方预警”后，明确改变图层标题与图例；不将两种颜色含义混合在同一图例中。点击区县查看详情。

没有源数据支持的预警边界时，使用来源行政区范围并标注“行政区范围示意”，不捏造危险区多边形。提供地区列表作为地图加载失败或低性能手机的替代入口。

### 4.3 地区详情与预警详情

地区详情展示逐小时雨量、过程时间、官方预警列表及变化记录。预警详情保留官方标题、正文、防御指南、发布机构与原始链接，明显标识解除信息。

### 4.4 展示状态

- 无有效预警：只有确认成功获取且覆盖该地区的数据时，显示“当前未获取到有效官方暴雨预警”，附时间。
- 请求失败、过期或地区不覆盖：显示“预警信息暂无法确认”，不能显示绿色安全状态。
- 缓存：显示缓存时间及过期状态，不以当前刷新时间掩盖源数据生成时间。
- 演示模式：全页面固定显示“演示数据，非实时气象信息”。

## 五、数据来源与接入决策

### 5.1 必需数据

| 数据 | 最低要求 | 接入前确认 |
|---|---|---|
| 官方暴雨预警 | 发布机构、产品类型、等级、原文、影响地区、发布与解除信息 | 授权、四川覆盖、更新和解除机制 |
| 降雨预测 | 区县或网格、每小时雨量、起报时间、有效时间、至少24小时窗口 | 分辨率、概率与误差说明、调用配额 |
| 降雨观测 | 观测时间、位置、累计时段与雨量 | 站点或网格覆盖、数据质量 |
| 行政区划与地图 | 地区编码、版本、合规底图与可用边界 | 地图服务授权、展示与署名要求 |

### 5.2 接入原则

官方内容核对入口包括四川气象服务网站、中国天气网预警页面，以及四川省政府公布的相关标准。公开可浏览网页不等于提供免费、稳定、可商用接口。

开发第一阶段应联系或选择具有明确授权的气象数据服务，确认 API、账号、使用条款、更新延迟、收费和商用限制。不将未经核实的抓取接口作为正式服务依赖；不承诺尚未验证的免费实时数据。

若暂时没有可靠官方预警接口，可开发演示版并提供官方页面入口，但不能对外声称已上线实时预警。若预测数据不足以计算开始时间和持续时间，应显示缺失说明，并将补足数据列为上线阻塞项。

## 六、技术实施建议

首版采用 React + TypeScript 实现响应式前端；地图使用支持合规中国底图的服务，供应商在授权与成本核对后确定。后端提供数据适配、缓存、地区匹配、预警生命周期处理及监控；可使用 Node.js 服务与数据库，供应商选型按实际数据规模决定。

流程：授权数据源 → 定时采集或源端推送 → 数据校验与标准化 → 缓存及存储 → 网站查询接口 → 地图与时间轴。预警更新、升级、降级和解除按来源事件标识处理，保留历史版本，避免旧版本覆盖新版本。

GitHub 仓库存放源代码与文档。GitHub Pages 可以承载前端，但不能直接运行常驻后端，接口密钥不能放在前端。正式服务需要独立后端或合适的托管函数。GitHub Actions 不作为分钟级实时预警采集的可靠保证。

建议目录：

```text
docs/              计划书、数据契约、来源核对记录
web/               网站前端
server/            数据接口与采集服务
shared/            地区、等级、时间规则和类型
tests/             关键规则和接入验证
```

### 6.1 数据契约

所有记录至少携带 source、sourceUrl、issuedAt、fetchedAt、validFrom、validTo、regionCode、regionName、dataStatus。预警增加 alertId、productType、level、issuer、lifecycleStatus 与 sourceVersion；预测增加 forecastRunAt、intervalStart、intervalEnd、precipitationMm、resolution、timeEstimateMethod、uncertainty。

源端缺失值保留为空，不以零填补。预警有效结束时间未知时不得根据固定时长自动标为解除，应显示“结束时间未提供”，并根据来源更新和新鲜度规则标记是否需要重新确认。

### 6.2 更新与可靠性目标

预警采集目标间隔1—5分钟，预测目标5—15分钟；实际频率受源数据更新和合同配额限制，必须注明这属于设计目标，并非当前能力。页面每分钟刷新状态，源数据未变化不伪造新预报。

为每类数据配置最大可接受延迟；超过约定阈值显示过期状态。监控成功率、源数据延迟、解析失败、地区匹配失败和解除传播延迟。处理限流、网络失败、重复事件、服务恢复及主备源冲突。

## 七、首版与后续范围

**首版必做：** 四川地区查询、官方预警分级、预测雨量等级、预测开始时间与持续时间、颜色区块、时间轴、来源与新鲜度提示、手机适配、演示和正式数据隔离。

**二期：** 订阅地区、浏览器通知、山洪和地质灾害官方信息、历史过程回看。通知须用户主动开启；浏览器关闭或系统限制时不能保证送达，不作为唯一应急提醒途径。

**暂不做：** 自研气象预测模型、签发官方预警、自动判断疏散路线、无来源的街道级风险判断。

## 九、预算规划

当前未确定数据服务商与部署商，无法给出可靠金额。预算表应分别核实：官方预警和预测数据费用、调用与流量配额、后端和数据库、地图服务、域名、开发与评审工时、运维成本。首版浏览器通知不默认引入付费短信。

询价后形成基础、增长两档月预算及费用上限；峰值访问按日常与暴雨集中访问两种场景估算。任何付费购买须另行确认。

## 十、验收标准

1. 四川市州和区县能够检索；无覆盖地区明确显示，不宣称全省逐街道精准。
2. 每条官方预警可核对发布机构、原文、等级、范围、发布时间和生命周期；升级与解除不会漏处理或重复呈现为新事件。
3. 页面显示降雨等级、预测开始时间、持续时间；无法确定时明确说明，不使用编造值。
4. 开始时间、预测过程时间和官方有效时间分别展示；跨天、已经开始、结束未知均正确处理。
5. 降雨色块始终附单位、累计时段和图例；预警颜色和降雨配色没有混用。
6. 等级边界0、0.1、10、25、50、100、250 mm与缺失值均通过规则验证；小时量不套用24小时阈值。
7. 断网、源端失败、限流、数据过期、地区编码变化和恢复场景均能正确展示状态；未获取数据不显示“无预警”。
8. 手机常见窄屏不出现遮挡；关闭地图仍能查看核心卡片；颜色之外有文字，大字模式可操作。
9. 试运行以可取得的四川历史事件回放及持续线上核对评估数据延迟、漏报、重复记录和预测时间误差，形成报告；不能仅以页面截图代替数据验证。
10. 计划书阶段验收为文档和仓库交付；正式网站验收需经过以上功能与数据验证，二者不能混淆。

## 十一、运营与维护

明确数据接入、技术运维和内容复核负责人；建立故障公告、回退和恢复流程。每次来源格式、行政区划或标准变更后进行复核。定位只在用户主动操作时使用，首版不持久存储精确坐标；密钥由后端环境变量管理。

暴雨期间优先保证卡片、地区列表和来源原文可用，地图故障不阻塞预警阅读。发生错误预警展示时及时更正并保留审计记录。

## 十二、待确认事项

- 是否采用“四川雨情”作为正式名称。
- 授权数据源、商业使用方式、区县及乡镇覆盖、更新时效和月预算。
- 首批试运行地区与数据对照对象。
- 预测时间信息的来源和可验证误差；不承诺分钟级准确度。
- 运营主体、正式部署域名，以及正式上线需要履行的事项。
